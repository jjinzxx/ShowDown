## 역할과 책임

| 담당 | 주요 책임 | 협업 지점 |
| --- | --- | --- |
| 임현진 | 연출 방향, 아트 톤, 레벨 통합 | 코어 이벤트를 화면 연출로 변환 |
| 김윤아 | 에셋 탐색, 배치 테스트, 맵 드레싱 | 플레이 가독성과 분위기를 함께 검증 |
| 이진헌 | 기술 통합, 멀티·DB·LLM, Git 병합 | 코어와 UI·연출·온라인 기능 연결 |
| 박형빈 | 카드, 베팅, 룰렛, 승패 판정 | 결과를 이벤트로 발행해 연출과 분리 |

## 개발 원칙

### 코어와 표현의 분리

게임 규칙은 카드 값, 베팅 수, 룰렛 결과와 생명 상태만 판단합니다. 카메라, 사운드, VFX와 UI는 코어가 발행한 이벤트를 받아 실행합니다. 이 구조를 통해 규칙 테스트와 연출 수정이 서로 영향을 덜 받도록 했습니다.

### 레벨 관리

- `.umap`은 텍스트 병합이 어려우므로 동시에 같은 레벨을 수정하지 않습니다.
- 신규 기능은 테스트맵에서 먼저 검증한 후 메인 레벨에 통합합니다.
- 메인 레벨 변경 전 담당자와 작업 시간을 공유합니다.
- 에셋 이동·이름 변경 후에는 Unreal Editor에서 Redirector를 정리합니다.

### Git 운영

- 기능 단위 브랜치에서 작업하고, 실행 가능한 단위로 커밋합니다.
- 코드와 에셋 변경이 함께 필요한 경우 커밋 목적을 명확히 나눕니다.
- `.uasset`, `.umap`, 이미지, 음원과 로컬 음성 런타임은 Git LFS로 관리합니다.
- API 키와 로컬 설정 파일은 커밋하지 않고 템플릿만 공유합니다.
- 병합 전 C++ 컴파일, 에디터 실행, 핵심 플레이 흐름을 확인합니다.

## 디렉터리 구조

```text
showdown/
├─ Config/                  # 엔진·게임·입력 설정
├─ Content/                 # 맵, Blueprint, UI, 오디오, 게임 에셋
├─ Source/ShowDown/         # C++ 게임 코드
│  ├─ Public/               # 공개 인터페이스와 타입
│  └─ Private/              # 구현 및 자동화 테스트
├─ SourceAssets/            # 재임포트 가능한 원본 음원·이미지
├─ Binaries/ThirdParty/     # Whisper·eSpeak NG 런타임
├─ supabase/                # 마이그레이션과 Edge Functions
├─ docs/                    # 협업 및 프로젝트 문서
└─ tools/                   # 빌드·맵·문서 보조 도구
```

## 품질 확인 항목

- 카드 선택부터 다음 라운드까지 코어 루프가 중단되지 않는가?
- 서버와 두 클라이언트에서 카드·베팅·룰렛 결과가 같은가?
- 카드와 총알 정보가 카메라 연출 중에도 읽히는가?
- 맵과 런타임 의존성이 패키징 결과물에 포함되는가?
- 실패 가능한 외부 API에 대체 흐름이 있는가?
- 비밀키, 로컬 로그와 생성 파일이 Git에 포함되지 않았는가?
